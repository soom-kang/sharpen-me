# 다음 한정 평가 계획안 (미승인)

이 문서는 실행 전 합의를 위한 계획안입니다. **유료 호출은 아직 하지 않았고, 범위·호출 수·예산이 승인되기 전에는 실행하지 않습니다.** 대상은 beta.8 이후 스킬 개정(P1 trigger·규칙 보강, P2 섹션·완료 점검·`Next:` 형식)과 관찰기 수정입니다.

## 실행 전에 끝난 관찰기 수정

[beta.7 보고서](evaluation-beta7-2026-10-26.ko.md)가 우선 과제로 꼽은 두 가지를 로컬 회귀 테스트와 함께 고쳤습니다.

- **Codex 명령 분류:** `-g '!**/SKILL.md'`, `--exclude=` 같은 제외 glob은 접근으로 세지 않습니다. `rg --files`, `find`, `ls`, `fd`는 discovery로 기록합니다. 스킬 경로를 명시하지 않은 `rg`·`grep` 검색은 출력에 나온 스킬 경로로 content 접근을 귀속합니다. 이에 따라 beta.7 D5 같은 넓은 검색은 FAIL로, 각주 1의 제외 glob은 증거 없음으로 관찰됩니다.
- **집계 우선순위:** 구조 판정이 `UNCLEAR`이고 수동 판정이 `FAIL`이면 `FAIL`로 집계합니다. 수동 판정이 구조적 `FAIL`이나 `NOT_RUN`을 덮어쓰지는 않습니다.

beta.7 기록에는 원시 provider stream이 없어 기존 관찰을 새 분류로 다시 계산할 수 없습니다. 수정의 효과는 다음 실행에서만 확인됩니다. 수정된 runner로 beta.7 archive를 summarize하거나 이어서 실행하지 않습니다.

## 제안 범위

| 묶음 | 사례 | 확인할 것 |
| --- | --- | --- |
| beta.7 결함 재확인 | D5 dedupe 넓은 검색, R2 challenge 외부 계약, R5 refine 자동 선택 | P1 규칙과 trigger 어휘가 같은 상황에서 결함을 줄이는지 |
| 그럴듯한 음성 사례 | 문법만 고치는 요청, 방금 실행한 테스트 결과 질문, 범위가 명확한 긴 rename 요청 | 스킬을 쓰지 말아야 할 때 쓰지 않는지(`expectedSkills: []`) |
| 미평가 스킬 | brief 2개(기준점 이후 변경과 오래된 blocker, 기준점 없는 snapshot), cold-review 2개(전제 조건이 빠진 문서, 독립 실행 확인) | 처음으로 직접 관찰 |
| P2 형식 | review 기본 severity, challenge의 `Next:` 한 줄 | 새 출력 관례가 지켜지고 응답이 과도하게 길어지지 않는지 |

모두 12개 사례입니다. 두 도구에서 각 1회 실행합니다.

## 스킬 미사용 대조군

같은 사례를 스킬 없이 실행하는 대조군을 둡니다. 스킬 선택 자체를 보는 음성 사례 3개와 독립 실행 여부를 보는 cold-review 1개는 대조군에서 의미가 없어 제외합니다. 대조군은 8개 사례 × 2개 도구 = 16회입니다. 대조군에서는 스킬 로딩 구조 판정을 적용하지 않고, 같은 기대 사실로 의미만 비교합니다. 한 번의 관찰이므로 개선 폭이나 일반 성공률은 주장하지 않습니다.

## 실행 전에 필요한 구현

- 이 계획을 담는 새 plan 파일과 runner: 기존 `evaluate-focused.mjs`의 저장·dispatch·Docker helper를 재사용하고, 대조군 arm에서는 스킬을 fixture에 복사하지 않습니다.
- beta.7 archive는 함께 저장된 `frozen/` 사본과 함께 그대로 보존합니다. `evaluate-focused.mjs`는 집계 우선순위만 바뀌었으므로, beta.7 결과를 다시 집계해야 하면 archive의 frozen 사본을 사용합니다.
- `--dry-run`으로 호출 목록과 유료 호출 0회를 확인한 뒤, 승인을 받아 pilot 4회 → 검토 → 나머지를 실행합니다.
