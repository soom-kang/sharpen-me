### SHARPEN-QA-003

**표준 credential 형식이 archive redaction을 통과함**

| Field | Value |
| --- | --- |
| Type / Component | Bug / evaluator security |
| Priority / Severity | P2 / Major, 해당 형식의 credential이 입력되는 경우 |
| Status / Confidence | Fixed locally; 수정 전 누락은 `[Verified]`, 실제 유출은 미확인 |
| Suggested owner | Evaluator maintainer |
| Location | [sanitize](../scripts/eval-observation.mjs), lines 98–102; [boundedEvidence](../scripts/eval-execution.mjs), lines 4–15 |
| Contract | [Evaluation](evaluation.md#result-format)의 credential-shaped value 제거 |

**Current State**

`sanitize`는 `Bearer:` 또는 `Bearer=` 형태를 찾지만 표준 `Authorization: Bearer <value>` 형태를 놓칩니다. JSON의 quoted key 뒤 구분자도 처리하지 못합니다. `boundedEvidence`가 이 함수를 그대로 사용하므로 해당 값이 command/result evidence에 남습니다. Observation 저장도 같은 함수를 사용합니다.

**Preconditions / Reproduction**

합성 placeholder만 사용합니다. 아래 명령은 provider를 호출하거나 파일을 쓰지 않습니다. Repository root에서 실행합니다.

```bash
node --input-type=module <<'NODE'
import { boundedEvidence } from './scripts/eval-execution.mjs';
for (const input of [
  'Authorization: Bearer QA_PLACEHOLDER',
  '{"api_key":"QA_PLACEHOLDER"}',
  'token=QA_PLACEHOLDER'
]) {
  console.log(boundedEvidence(input, '/synthetic/fixture')
    .text.includes('QA_PLACEHOLDER'));
}
NODE
```

**Observed Result:** `true`, `true`, `false`. Assignment control은 제거되지만 header와 JSON 값은 남습니다.

**Impact**

위 형식의 실제 credential이 provider response나 command output에 들어오면 local records와 review packet에 보존될 위험이 있습니다. 실제 credential, 기존 raw archive, 사용자 인증 설정은 이 QA에서 읽지 않았습니다. 공개 유출이나 계정 침해를 주장하지 않습니다.

**Expected State / Requested Change**

지원할 credential 형식을 명시하고 Bearer header, quoted JSON field, assignment를 같은 경계에서 처리합니다. JSON 구조는 유지합니다. 알려진 패턴 redaction이 모든 민감 정보의 제거를 보장한다고 표현하지 않습니다.

**Acceptance Criteria**

1. 합성 Bearer header, quoted credential fields, assignment의 값이 persisted observation과 blind packet에 남지 않습니다.
2. JSON quoting, whitespace, case 차이를 처리하며 정상 문자열과 구조를 손상시키지 않습니다.
3. 기존 `test/eval-observation.test.mjs`, `test/eval-execution.test.mjs`에서 관련 regression만 확인합니다. 별도 framework나 live provider는 필요하지 않습니다.
4. 지원 범위와 미지원 범위를 documentation에 반영합니다.

**Validation:** 위 probe에서 누락을 재현했습니다. 수정 후 acceptance 검증은 `NOT_RUN`입니다.

| Field | Value |
| --- | --- |
| Type / Component | Bug / evaluator archival, resume accounting |
| Priority / Severity | P2 / Major |
| Status / Confidence | Fixed locally; 수정 전 JSON 손상 및 상태 손실은 `[Verified]` |
| Suggested owner | Evaluator maintainer |
| Location | [sanitize](../scripts/eval-observation.mjs), line 101; [evaluate](../scripts/eval-v3.mjs), line 205; [dispatchMatrix](../scripts/eval-v3-contract.mjs), lines 75–79 |
| Recovery boundary | [resume journal validation](../scripts/eval-v3.mjs), lines 149–151 |

**Current State**

`evaluate`는 observation을 JSON으로 직렬화한 뒤 일반 텍스트 regex로 redaction하고 다시 parse합니다. 문자열 끝의 `token=...` 또는 `password: ...`를 치환할 때 regex가 JSON의 닫는 따옴표까지 소비합니다. 마지막 parse는 `evaluate`의 `try/catch` 밖에 있습니다.

**Preconditions / Reproduction**

```bash

import { dispatchMatrix } from './scripts/eval-v3-contract.mjs';

  testCase: { id: 'synthetic-json' }, repeat: 1 };
const records = await dispatchMatrix([item], new Map(), async () => {
  return JSON.parse(sanitize(JSON.stringify({
    providerCalled: true, status: 'REVIEW_REQUIRED',
    output: 'token=QA_PLACEHOLDER'
  }), '/synthetic/fixture'));
}, async (_item, result) => result, async () => {});
console.log(JSON.stringify(records));
NODE
```

**Observed Result:** `[{"status":"NOT_RUN","reason":"HARNESS_ERROR","providerCalled":false}]`. `token=...` 및 `password: ...`의 JSON round trip은 모두 실패했고 ordinary response control은 성공했습니다.

**Impact**

실제 실행 경로는 journal을 기록하고 `providerCalled:true`로 전환한 뒤 observation을 수집합니다. 위 오류가 밖으로 나오면 dispatcher는 호출 여부를 잃고 uncalled로 저장합니다. 응답 evidence 손실, attempt count 과소 집계, journal 불일치가 발생합니다. Resume는 불일치를 감지해 안전하게 차단합니다. 자동 재호출이나 이중 과금은 입증하지 않았습니다.

**Expected State / Requested Change**

String leaf를 구조적으로 redact한 후 JSON으로 직렬화합니다. Provider 호출을 시도한 뒤 발생한 오류에서도 durable journal과 `providerCalled`가 일치하도록 오류 observation을 보존합니다. 과거 archive를 추측으로 고치거나 덮어쓰지 않습니다.

**Acceptance Criteria**

1. 문자열 끝 credential pattern과 nested string을 처리해도 JSON round trip과 field types가 보존됩니다.
2. 호출 후 수집·redaction 오류는 `providerCalled:true`와 오류 이유를 유지하며 journal의 attempt count와 일치합니다.
3. 호출 여부를 확인할 수 없는 interruption은 현재처럼 resume를 차단하고 manual investigation을 요구합니다.
4. 기존 observation/v3 tests에 정상 control, 문자열 끝 pattern, 호출 후 수집 실패의 최소 regression을 추가합니다.

**Validation:** 정상·실패 입력과 dispatcher fallback을 local synthetic 입력으로 재현했습니다. 실제 provider와 archive recovery는 `NOT_RUN`입니다.

### SHARPEN-QA-005

**halt 이후 대기 중이던 provider lane이 신규 호출을 시작함**

| Field | Value |
| --- | --- |
| Type / Component | Bug / async dispatch coordination |
| Priority / Severity | P2 / Major, 평가 중지 계약 위반 |
| Status / Confidence | Fixed locally; 수정 전 interleaving은 `[Verified]` |
| Suggested owner | Evaluator maintainer |
| Location | [dispatchMatrix](../scripts/eval-v3-contract.mjs), lines 75–80; [actual dispatch preparation](../scripts/eval-v3.mjs), lines 186–188 |
| Contract | [Maintenance](maintenance.md#live-evaluation-and-resume)의 신규 dispatch 중지 및 이미 실행 중인 peer 완료 허용 |

**Current State**

Shared `halt`는 `await assertInputs()` 전에만 확인됩니다. 다른 lane이 이 대기 시간에 quota, authentication 또는 isolation 실패로 중지해도 다시 확인하지 않고 `execute`를 시작합니다. Evaluator 내부에도 실제 provider spawn 전에 awaited 준비 단계가 있습니다.

**Preconditions / Reproduction**

```bash
node --input-type=module <<'NODE'
import { dispatchMatrix } from './scripts/eval-v3-contract.mjs';
let releasePeer, stopRecorded;
const peerGate = new Promise(resolve => { releasePeer = resolve; });
const stopGate = new Promise(resolve => { stopRecorded = resolve; });
let validations = 0;
const events = [];
const matrix = ['codex', 'claude'].map(provider => ({ provider,
  version: 'after', testCase: { id: 'synthetic-halt' }, repeat: 1 }));
const running = dispatchMatrix(matrix, new Map(), async item => {
  events.push(`execute:${item.provider}`);
  return { status: 'NOT_RUN', providerCalled: true,
    reason: item.provider === 'codex' ? 'QUOTA_OR_BUDGET' : 'TIMEOUT' };
}, async (item, result) => {
  events.push(`persist:${item.provider}:${result.reason}`);
  if (item.provider === 'codex') stopRecorded();
  return result;
}, async () => { if (++validations === 2) await peerGate; });
await stopGate;
releasePeer();
await running;
console.log(JSON.stringify(events));
NODE
```

**Observed Result:** `execute:codex` → `persist:codex:QUOTA_OR_BUDGET` → `execute:claude` → `persist:claude:TIMEOUT`.

**Impact**

이미 실행 중인 peer의 완료가 아니라 halt 후의 신규 호출입니다. 현재 두 lane 구조에서는 대기 중이던 peer가 추가 유료 호출을 시작할 위험이 있습니다. `maxCalls` 상한 우회나 실제 추가 과금은 확인하지 않았습니다.

**Expected State / Requested Change**

Input verification 이후와 실제 dispatch 직전에 동일한 stop 상태를 확인합니다. Evaluator의 async 준비와 journal write도 실제 spawn 경계와 조정합니다. 이미 실행 중인 peer의 결과는 보존하며, 단순히 모든 peer를 취소하는 변경은 요구하지 않습니다.

**Acceptance Criteria**

1. Verification 또는 fixture 준비 중인 peer는 halt 후 provider를 시작하지 않고 uncalled observation을 남깁니다.
2. Halt 전에 시작한 peer의 결과와 attempt count는 보존됩니다.
3. Quota, auth, isolation failure와 journal write 대기 순서를 기존 `test/eval-v3.test.mjs`의 deterministic gates로 검증합니다.
4. 정상 실행의 provider별 serial 처리, 전체 concurrency 2, `maxCalls`를 유지합니다.

**Validation:** 위 순서를 재현했습니다. 실제 provider interruption은 `NOT_RUN`입니다.

이번 수정 시작 시 존재한 README 2개와 evaluation·maintenance 변경, untracked QA 보고서를 보존했습니다. 현재 변경 범위는 evaluator 5개 modules, 기존 test 파일 4개, 관련 문서 7개입니다. Commit·push, 유료 provider 호출, 외부 JIRA 등록, release, scheduler activation은 하지 않았습니다. Historical archives와 보호된 설정도 수정하지 않았습니다.

`NOT_RUN`: 실제 Docker isolation은 최초 QA에서 daemon 미실행으로 차단됐으며 관련 Docker 구성은 변경하지 않아 이번에 반복하지 않았습니다. Provider inference는 사용자가 금지했습니다.
